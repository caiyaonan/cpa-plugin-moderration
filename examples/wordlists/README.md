# 示例词库

这些词库用来在请求发往上游之前，**拦截**明显违反 OpenAI / Anthropic 使用政策的内容。它们只是起点：

- 上游没有公开过“封号关键词表”，账号处置依据的是使用政策和语义分类，所以词库**不能保证不封号**。
- 通用违规（暴力、色情、仇恨、自残等）主要靠 OpenAI 审核按语义判断；词库用来补充明确的高风险短语和业务规则。
- 账号共享或转售、异常地区 IP、高频自动化等与内容无关的原因，词库无法解决。

## 文件

| 文件 | 用途 | 类型 |
|---|---|---|
| `jailbreak.txt` | 越狱 / 绕过安全限制的话术（上游会标记反复越狱的账号） | 关键词 |
| `weapons.txt` + `weapons.regex.txt` | 大规模杀伤性武器、爆炸物制作 | 关键词 + 正则 |
| `malware.txt` | 恶意软件、网络攻击工具 | 关键词 |
| `fraud.txt` | 诈骗、洗钱、伪造证件 | 关键词 |
| `extremism.txt` | 恐怖主义、暴力极端主义 | 关键词 |
| `self-harm.txt` | 自残、自杀方法 | 关键词 |
| `privacy.regex.txt` | 身份证号、手机号、邮箱、API Key 等隐私数据 | 正则 |
| `image-nudity.txt` | **生图业务**：裸露、裸体描述（生图接口的安全系统比审核接口更严，这类提示词常被生图接口拒绝而审核接口放行） | 关键词 |

涉及未成年人的性内容不提供词表，请依靠 OpenAI 审核：保持规则的“检查文本”和“检查图片”都开启（`sexual/minors` 类别插件已强制始终拦截）。

## 生图业务建议

OpenAI 生图接口（gpt-image-*）自带的安全系统比审核接口严格：成年人裸体、真人写实的性感暴露画面，审核接口往往不会判定违规，但生图接口会以 `moderation_blocked`（`categories: ["other"]`）拒绝。被拒次数多了，同样会让上游账号被标记。建议生图规则同时使用两道防线：

1. 挂上 `image-nudity.txt` 词库：确定性拦截明确的裸露描述；
2. 在规则的「更严格的分数阈值」里设置 `sexual` 0.2 左右（起步值），再根据「审核记录」里显示的分数调整。

## 导入方法

1. 打开插件管理页 `/v0/resource/plugins/cpa-moderation/ui` →「词库」→「新建词库」，填写 ID 和名称（例如 `jailbreak` / 越狱话术）。
2. 关键词文件：点「导入 txt」选择对应的 `.txt` 文件（必须是 UTF-8 编码）。
3. 正则文件（`*.regex.txt`）：用文本编辑器打开，把内容复制到「正则表达式」框里，每行一条。
4. 点顶部「保存」。
5. 到「审核规则」里，在需要的规则上勾选这个词库并保存，**勾选之后才会生效**。

## 注意事项

- 匹配前会对文本做 NFKC 规范化、转小写、去掉零宽字符，所以关键词不区分大小写和全角半角；**正则也是在转成小写之后的文本上匹配的**，要按小写来写。
- 关键词按子串匹配：`钓鱼网站模板` 不会误伤“钓鱼”，但太短的词（尤其是单字）几乎一定会误报。
- **编程类业务（Claude Code、Codex 等）慎用 `malware.txt`**：安全开发中常有相似的说法。建议只挂在非编程业务的规则上。
- `self-harm.txt` 命中后请求会被直接拒绝（403），用户看不到上游模型通常会给出的求助建议。请根据业务决定是否启用。
- `privacy.regex.txt` 会拦截包含手机号、邮箱的正常请求（例如让模型整理通讯录）。只适合明确不允许传输个人信息的业务。
- 先少量启用，观察「审核记录」：拦截原因会显示为 `wordlist:<词库ID>/keyword#<行号-1>` 或 `regex#<序号>`，对照文件就能找到是哪一条导致的误报。

这些文件由 `internal/rules/examples_test.go` 校验：正则必须能编译，样例违规语句必须命中，常见的正常语句不能误报。
